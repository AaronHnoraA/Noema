# Noema 编辑器的 Vim 按键

**原生 Vim 是标准。** 命令的结果（文本和光标落点）以 Neovim 的实际行为为准，
而不是凭记忆：`scripts/record-vim-parity.mjs` 把一张命令表交给 Neovim 执行并
记录结果，`tests/vim-native-parity.test.ts` 要求 Noema 逐条复现。下面列出的
差异是有意保留的，其余任何不同都算缺陷。

屏幕行这一点沿用 AaronEmacs 的 Evil 配置。该配置启用
`evil-respect-visual-line-mode`；所以这里的“行”优先指屏幕上看见的一行，
长段落自动换行后，每一行都是 `j/k` 和行操作的独立目标。隐藏的 Markdown
标记（标题的 `## `、引用的 `>`）属于它所在的那一行，不单独成行：`V` 选中标题
时连同标记一起选中，`j` 每次正好走一行。没有可测量布局
（例如编辑器隐藏或无界面的测试）时，按源码行回退。渲染成单个部件的展示公式
算一行。

| 按键 | Noema 中的目标 |
| --- | --- |
| `j/k`、`0/$`、`g^`、`V` | 屏幕行；`g^` 到屏幕行首个非空字符 |
| `gj/gk`、`g0/g$`、`^`、`g_` | Markdown 源码行；`^` 到首个非空字符（全是空白的行到最后一个字符），`g_` 到最后一个非空字符 |
| `dd/yy/cc`、`Y` | 当前屏幕行；计数扩展到后续屏幕行 |
| `D/C` | 从光标到当前屏幕行尾；计数可扩展到后续屏幕行 |
| `f/F/t/T` | 只在当前屏幕行查找字符；`;`、`,` 重复查找 |
| `gg/G`、`+/-/_` | 源码行号和源码行边界 |
| `w/b`、`W/B` | 下一个／上一个词的**开头**；大写版本将连续非空字符视为一个 `WORD` |
| `e/ge`、`E/gE` | 当前或前一个词的**末尾** |

小写 `word` 将字母、数字、下划线与标点序列分开，空行也算一个词。
例如光标在 `LCE (Linear Code Equivalence)` 的 `L` 上，依次按 `w` 会
到 `(`、再到 `Linear` 的 `L`；按 `e` 会到 `LCE` 的 `E`。字符可视模式的
`w/W` 将光标移到下一个词首，但选区停在该词之前，因此 `vw` 不会多选
下一个词的首字符；词间空白仍在选区中。`ve` 停在当前词尾。只选词本身
可用 `viw`，连相邻空白一起选可用 `vaw`；已有选区时再按 `iw`/`aw`/`ip`/`ap`
会继续向后扩一个对象。这是 Noema 的 Visual 词移动约定；Vim 默认 Visual 会
包含光标下的终点字符。向后的 `b/B` 仍落在词首：从词尾按 `vb` 会选中这个词，
再按一次会延伸到上一个词首。

字符可视模式的光标可以停在换行符上，和 Vim 一样：`l`、`$`，以及目标列超出
行长的 `j/k` 都能到达。所以 `v$d` 会连换行一起删掉，把下一行并上来。

`d`、`c`、`y` 与移动命令组合时沿用 Vim 的排他／包含端点规则。例如
`dw` 删除到下一个词首之前，`de` 包含词尾，`cw` 在词内按 `ce` 处理。
行尾最后一个词上的 `dw` 只删到行尾，不会把下一行并上来；排他移动若停在
后一行的第 0 列，范围退到前一行行尾，起点又在缩进里时整行删除
（`:h exclusive-linewise`）；跨行的 `d` 若起点前、终点后都只有空白，同样
整行删除（`:h d`）。`Y` 与 Evil 一样复制整行，`D` 才删除到行尾。
普通模式下不能用未绑定的可打印键修改文档。

`u` 撤销一条命令，`Ctrl-r` 重做，`.` 重复上次修改。一条命令就是一步：
`cwfoo bar<Esc>` 之后按一次 `u` 就恢复原词，尽管编辑器的历史里它是一次
删除加上每个词一次输入（`Cmd-Z` 仍按编辑器的粒度逐词撤销）。撤销后光标
回到该命令修改文本时所在的位置，例如 `diw` 回到词首，`dd` 回到行首非空
字符；重做也落在同一处。从磁盘重新载入但内容未变（例如连接恢复后的对账）
不会清空撤销历史。

离开 Insert 时光标左移一格，和 Vim 一样，无论是否输入了内容。唯一的例外
是从公式等渲染部件进入 Insert：部件是一个字符，光标回到部件上。

Normal 和 Visual 模式把白名单内的渲染部件当作一个字符和一个词：公式、
图片、脚注标记、块引用、块 ID 标记、任务复选框，以及折叠代码或 Mermaid
占位部件。`h/l/w/b/e`、字符选择和 `diw/cw` 不进入它们隐藏的源码。
行内代码、普通链接文字和表格单元格仍按可见文字移动。进入 Insert 模式
不会改变当前的渲染／源码视图；在渲染视图中，光标进入部件时沿用编辑器
原有的局部展开和编辑行为。Vim 不负责切换整个文档的视图。

Noema 在 Normal、Visual 和 Visual-line 中用 `s/S` 向前／向后屏幕跳转；
Visual 跳转延长当前选区。`/` 打开查找面板作为搜索提示符：回车接受当前
匹配并回到正文（Normal 模式，光标在匹配开头），`n`/`N` 继续向后／向前找，
`Esc` 取消并回到搜索前的位置。用 `Cmd-F` 打开的面板不变，回车仍是下一个。
矩形可视模式、宏、Ex 命令不在此轻量层的实现范围：`q`、`@`、`Z` 会连同
后面那个键一起吃掉并提示未绑定，不会让 `qa` 的 `a` 掉进 Insert。文档编辑
仍可通过 Emacs 宿主提供的 Evil 使用这些能力。

## 标记、跳转表和寄存器

- `ma`–`mz` 设标记；`` `a `` 回到标记处，`'a` 回到标记所在行的首个非空字符。
  两者都是移动命令，可以接操作符（`d'a`）。标记随文本编辑移动。
- `gg`、`G`、`{`、`}`、`%`、`n`/`N`、`*`/`#`、`H`/`M`/`L` 和标记跳转会记入
  跳转表：`Ctrl-o` 往回走，`Ctrl-i` 往前走，` `` ` 和 `''` 回到上一次跳转前的位置。
- `gi` 回到上次离开 Insert 的位置继续输入。
- `"a`–`"z` 是命名寄存器，大写名追加；`"0` 是最近一次复制（删除不会覆盖它）；
  `"_` 是黑洞寄存器，删除时不进任何寄存器。不指定时用未命名寄存器，它和系统
  剪贴板相通。寄存器只对紧跟着的那一条命令有效。

## Ctrl 组合键

Insert 之外，`Ctrl` 组合键要么是 Vim 的命令，要么什么都不做，绝不修改文本
（CodeMirror 在 macOS 上给 `Ctrl-d/h/k/o/t` 绑了 Emacs 风格的编辑命令，以前
会在 Normal 模式下删字、开新行）。

| 按键 | 作用 |
| --- | --- |
| `Ctrl-d` / `Ctrl-u` | 向下／向上半页，光标在屏幕上的位置不变 |
| `Ctrl-f` / `Ctrl-b` | 向下／向上一页 |
| `Ctrl-e` | 页面向下滚一行 |
| `Ctrl-o` / `Ctrl-i` | 跳转表后退／前进 |
| `Ctrl-r` | 重做 |
| `Ctrl-h`、`Ctrl-j`/`Ctrl-n`、`Ctrl-p`、`Ctrl-m` | 同 `h`、`j`、`k`、回车 |

`Ctrl-x`、`Ctrl-c`、`Ctrl-g` 仍交给 Emacs。

## 输入法

Insert 之外，输入法接管的按键既不是命令也不是文字，直接丢弃：拼音开着时按
`j`，光标不动，输入法也不会往笔记里写字。判断依据是按键本身（正在组字、
`keyCode` 229、或直接打出的非 ASCII 字符，见 `inputMethodKey`），所以切回
英文布局后同一个键立刻恢复为命令。`Esc` 始终有效。Emacs 宿主路径
（`xwidget-key-guard.ts`）在所有命令分支之前做同样的判断；组字过程中写进
页面的文字由一个事务过滤器拒绝。

## 与原生 Vim 的有意差异

- `s/S` 是屏幕跳转，不是替换。
- Visual 的 `w/W` 不选中下一个词的首字符（见上）。
- 字符可视模式的 `I` 在选区开头插入（Evil 的行为）；Vim 在行首插入。
- `o`/`O`/`cc` 沿用 Markdown 的续行前缀和缩进，相当于开着 `autoindent`。
- `{`/`}` 和 `ip`/`ap` 把只含空白的行也当作段落分隔；Vim 只认空行。
- 括号对象（`di(` 等）只在光标位于括号内时生效，不向后搜索。
