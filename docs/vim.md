# Noema 编辑器的 Vim 按键

Noema 的模态编辑以 AaronEmacs 的 Evil 配置为参照。该配置启用
`evil-respect-visual-line-mode`；所以这里的“行”优先指屏幕上看见的一行，
长段落自动换行后，每一行都是 `j/k` 和行操作的独立目标。没有可测量布局
（例如编辑器隐藏或无界面的测试）时，按源码行回退。渲染成单个部件的展示公式
算一行。

| 按键 | Noema 中的目标 |
| --- | --- |
| `j/k`、`0/$`、`g^`、`V` | 屏幕行；`g^` 到屏幕行首个非空字符 |
| `gj/gk`、`g0/g$`、`^` | Markdown 源码行；`^` 到源码行首个非空字符，空白行到行首 |
| `dd/yy/cc`、`Y` | 当前屏幕行；计数扩展到后续屏幕行 |
| `D/C` | 从光标到当前屏幕行尾；计数可扩展到后续屏幕行 |
| `f/F/t/T` | 只在当前屏幕行查找字符；`;`、`,` 重复查找 |
| `gg/G`、`+/-/_` | 源码行号和源码行边界 |
| `w/b`、`W/B` | 下一个／上一个词的**开头**；大写版本将连续非空字符视为一个 `WORD` |
| `e/ge`、`E/gE` | 当前或前一个词的**末尾** |

小写 `word` 将字母、数字、下划线与标点序列分开，空行也算一个词。
例如光标在 `LCE (Linear Code Equivalence)` 的 `L` 上，依次按 `w` 会
到 `(`、再到 `Linear` 的 `L`；按 `e` 会到 `LCE` 的 `E`。字符可视模式的
`w/W` 将光标移到下一个词首，但选区停在该词之前，因此 `vw` 不会多选
下一个词的首字符；词间空白仍在选区中。`ve` 停在当前词尾。只选词本身
可用 `viw`，连相邻空白一起选可用 `vaw`。这是 Noema 的 Visual 词移动
约定；Vim 默认 Visual 会包含光标下的终点字符。向后的 `b/B` 仍落在词首：
从词尾按 `vb` 会选中这个词，再按一次会延伸到上一个词首。

`d`、`c`、`y` 与移动命令组合时沿用 Vim 的排他／包含端点规则。例如
`dw` 删除到下一个词首之前，`de` 包含词尾，`cw` 在词内按 `ce` 处理。
`Y` 与 Evil 一样复制整行，`D` 才删除到行尾。`u`、`Ctrl-r` 和 `.` 分别
用于撤销、重做、重复上次修改。普通模式下不能用未绑定的可打印键修改文档。

Normal 和 Visual 模式把白名单内的渲染部件当作一个字符和一个词：公式、
图片、脚注标记、块引用、块 ID 标记、任务复选框，以及折叠代码或 Mermaid
占位部件。`h/l/w/b/e`、字符选择和 `diw/cw` 不进入它们隐藏的源码。
行内代码、普通链接文字和表格单元格仍按可见文字移动。进入 Insert 模式
不会改变当前的渲染／源码视图；在渲染视图中，光标进入部件时沿用编辑器
原有的局部展开和编辑行为。Vim 不负责切换整个文档的视图。

Noema 在 Normal、Visual 和 Visual-line 中用 `s/S` 向前／向后屏幕跳转；
Visual 跳转延长当前选区。`/` 打开宿主查找面板。寄存器目前只有未命名
寄存器；矩形可视模式、宏、Ex 命令不在此轻量层的实现范围。文档编辑仍可通过
Emacs 宿主提供的 Evil 使用这些能力。

参考：[Vim motion.txt](https://vimhelp.org/motion.txt.html)、
[Vim visual.txt](https://vimhelp.org/visual.txt.html)，以及 AaronEmacs 所安装
Evil 的 `evil-integration.el`、`evil-commands.el` 和 `evil-types.el`。
